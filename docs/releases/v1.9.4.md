# v1.9.4 · 夜航不停

修复手机实机普通层换层后画面停住，以及同一进程再次开局出现黑屏的问题。

## 根因与修复

`processEvents` 原来直接遍历 `run.events`。收到 `upgrade` 后，普通层自动领奖会连续调用 `chooseUpgrade`，将下一次强化、刻印、路线和换层事件追加到同一数组。遍历继续读到了追加的旧 `upgrade`；此时已经进入下一层，`ensureDraft` 返回 `null`，`appendDraftCards` 读取其 `key` 抛错。动画回调尾部的下一帧未能注册，所以战斗、冷却和场景停止，再开新局仍没有绘制回调。

现在每批事件使用快照，完成反馈后再根据当前状态打开选卡。自动领奖新增的反馈在换层完成后单独消费一次；已经结束的选卡通知不会打开空面板。普通层继续自动领奖、自动进入下一层，第五层首领仍保留手动奖励和路线选择，刻印与武器进化反馈正常保留。

动画调度增加异常保护：意外绘制错误会暂停战斗、尝试保存并提供继续/返回邮局入口，下一帧调度保持有效。保存失败时不显示“已保存”。继续、恢复选卡和重新开局都会解除异常暂停。

## 验证

- 修复前，新增 UI 回归在实际战斗赚取的第 1、2、3 层清场事件上均重现 `Cannot read properties of null (reading 'key')`；原有 227 项规则测试仍全部通过，说明此前缺少界面事件重入覆盖。
- 新增 9 项行为回归：前三层自动领奖与持续帧更新、过期选卡事件、首领手动选择、战斗/选卡绘制异常恢复、异常后重新开局、保存失败提示。执行仓库实际发布的 UI 函数，房间检查点由原有玩家动作策略正常战斗取得。
- Android 新增第 7 个真 WebView 用例：仅通过光环、补给、界面推荐选择完成前三层；检查第四层存档、刻印、时间持续推进、Canvas 有实际场景、恢复同一旅途和新第一层启动。保留原有 6 个用例及全部断言、双横屏截图、离线和存档恢复门禁。
- 沿用既有 CI：规则/静态检查、Android 编译/设备验收、实际 Windows EXE 验收、三端资源哈希一致后，才发布正式 APK/EXE/网页 ZIP 与 Pages。

存档 schema 3、存储键、Android 包名与签名身份不变。源码、网页版本、离线缓存、Windows 包版本同步为 1.9.4；安装新版 APK 可覆盖原版保留数据。正式下载及各平台验收状态以关联 GitHub Actions 和 Release 为准。
