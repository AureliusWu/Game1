历史基线针对 v1.1.1，制定 v1.2.0 方案时采集。调查开始的 main 为 `90946be9072324d279399863f4bdffdefc863d73`；运行模块 SHA-256 保存在统计 JSON 中。

## 复跑

```bash
node scripts/balance-audit.mjs
```

使用 Node 内置模块和 `tests/journey-bot.mjs`，无新增依赖。按 package.json 版本输出对应 `v版本-baseline.json`、`v版本-samples.csv` 与 `v版本-stalls.json`；保留其他版本文件。统计 JSON 记录全部运行资源和分析脚本的 SHA-256，`sourceCommit` 为运行开始时的仓库 HEAD，实际执行的工作区文件以哈希为准。

- 常规旅途：种子 1001–1020，三档难度，新档/满课程+折光黎明灯预设，直送/三封信/分享灯火路线，360 次。
- 驻灯探针：种子 1001–1010，三档难度，新档，实际点亮第一盏灯后移动到灯下驻留 120 秒，只有自动光弹，30 次。该策略不要求到达结局。
- 驻灯首领：同一组 10 种子和三档难度，新档，实际完成点灯与前两章后，在首领阶段移动到附近灯塔驻留；整局禁用光环，不使用冲刺/补给，30 次。

所有移动、采集、支付、受伤、掉落、首领和出口均经过实际模拟。测试策略不直接改坐标、生命、金币或结局，不绕过首领。满成长档是声明的测试预设，不是真实玩家账户数据。

`observe` 和 `stopWhen` 只用于读取状态及结束探针；`camp`、`campBoss` 和 `noPulse` 仅决定导航目标或是否操作技能。默认 QA 策略行为保持。

## 解读限制

机器人知道地图位置、使用网格寻路，不包含人类反应、阅读或菜单决策。成功比例不估算玩家胜率，模拟时长也不是玩家游玩时长。

`time` 包含 1200 秒仍未结束的截断样本；`winTime` 只统计已通关样本。`unfinished` 与 `lost` 分列。最终血量包含恢复，不能单独证明战斗缺乏压力。

中位数和 p90 均在排序后的 `(n−1)×q` 位置线性插值，偶数样本的中位数取中间两个值的平均。原分析将偶数样本取为较小的中间值，本次接续已修正并重新运行；全部 420 次实验的既有观测值保持一致。标准驻灯星砂/经验中位数为 110/165，长夜为 132/198。

`firstRunStamps` 仅为新档终局快照的奖励估算；满成长档和未结束探针留空。途中触发、终局时已不满足的临时套装成就可能未计入，实际应用中的分段记录会保留这些奖励。

`v1.1.1-stalls.json` 自动保留未结束的 5 个旅途策略样本及末段 3 次状态（间隔 20 秒），无需另一套手动采集命令。结果提示追击/策略僵持，需要区分敌人寻路问题、机器人目标选择及玩家可主动换位的情况。驻灯探针记录 `campEstablished` 和实际 `campElapsed`；后续版本若在首盏灯前失败，资源增量留空，不把缺失观测写成零收益。

## v1.2.0 实装验证

新版记录为 `v1.2.0-baseline.json`、`v1.2.0-samples.csv`、`v1.2.0-stalls.json` 和独立复核 `v1.2.0-validation.json`。在新版 checkout 运行同一分析命令；历史 v1.1.1 数据需在包含原运行资源与原策略的 `45bbfb2ef94d60191a6bb39b035d8408fc056183` 提交复跑，不用新版机器人替代旧基线。分析期间运行资源或策略发生变化时脚本拒绝输出混合证据。

总计 840 次：原三路线矩阵 360、驻灯探针 30、驻灯首领 30、三流派 × 三难度 × 20 种子 180、公平配置 × 六组条件 × 20 种子 240。六组为常规、四项独立条件和四项叠加。构筑组的 `fresh` 指零级课程、只预先发现并携带该流派一盏启程灯；三件套其余部件均在真实旅途中获取。

结果：360 次主动旅途、180 次构筑旅途、240 次公平航线全部到达结局。30 次驻灯首领中 23 次到达结局、7 次死亡，无超时；30 个驻灯探针仍明确列为未结束观察。长夜驻灯首领 3/10 到达结局，漫游与标准各 10/10；不能把这些比例推广为真实玩家胜率。

第一章驻灯 120 秒的额外星砂中位数在标准/长夜均为 40，经验均为 72；有限巡逻结束后不继续增长。标准三封信策略结算星砂中位数仍为 229.5，说明单一机器人只购买/锻造部分行装时仍有余量，不能仅凭限制无限刷取就宣称所有经济选择已最优。

独立 Python 复核 1032 组指标分布的中位数、p90、最小/最大值；120 对公平挑战的新档/满成长档观测完全相同（不含用于标注的 profile 和奖励估算列）。17 个运行资源哈希和两份分析脚本哈希匹配。

本轮新策略会回应方向预警、主动接近首领，并为购物保留资金，不能将其与旧机器人的成功比例直接当作同策略版本因果对照。浓雾对机器人全图寻路的影响未建模；视觉效果另经界面检查。

## v1.3.0 无尽夜航

运行 `node scripts/endless-audit.mjs`，生成 `v1.3.0-endless-samples.csv` 和 `v1.3.0-endless-summary.json`。144 次操作策略实验：72 次主动推进均达到预设 15 层后封存，48 次路线变化中 47 次达到预设 10 层、1 次死亡，24 次不操作探针全部死亡，无超时样本。详见 [QA](../QA_v1.3.0.md)。

“封存”是策略主动停止，不能理解为无尽模式有 10/15 层结局。样本只验证真实掉落、移动、技能、首领、选择和保存的连贯性，机器人知道全图，不能估计玩家胜率。JSON 中记录全部 18 个资源和本次策略/脚本的 SHA-256；输入改变时脚本拒绝输出结果。原三章旅途的历史实验继续保留。
